# Static analysis and quality gates

Source: Development Standards Wiki → *Clean Code* → *Static Analysis and Quality Gates*. Cite rules as
`Static Analysis and Quality Gates / R<n>`. **Fix findings; do not suppress them.** Numeric thresholds exist only in
the shared configuration — never add, copy or relax one in a repository.

## 1. Shared analyzer configuration

Pivot.Framework does **not** ship an analyzer meta-package (there is no equivalent of the former `Bricks.CodeQuality`).
The shared set is therefore declared once per repository in `Directory.Build.props`, with versions pinned centrally:

- 🔴 **R1.** Every repository references exactly this analyzer set, declared only in `Directory.Build.props`: .NET SDK analyzers (`AnalysisLevel`), `SonarAnalyzer.CSharp`, `StyleCop.Analyzers` (naming, layout and documentation rules only), `Meziantou.Analyzer`. Never add them per project, never add other analyzer packages without an ADR, never copy rule sets.
- 🔴 **R2.** Versions pinned in `Directory.Packages.props` (central package management); `PackageReference`s carry no `Version`.
- 🔴 **R3.** Numeric thresholds (method length, complexity, parameters, coupling, duplication) live only in the shared `.editorconfig` / SonarCloud quality profile.
- 🔴 **R4.** The root `.editorconfig` is the organizational one. Local additions allowed; relaxing a 🔴 rule needs a waiver ADR and a `## Tooling deviations` entry in `README.md`. Required local additions for the Pivot conventions:
  ```ini
  dotnet_diagnostic.SA1124.severity = none    # regions are mandatory (csharp-regions)
  dotnet_diagnostic.SA1123.severity = error   # but never inside members
  dotnet_diagnostic.SA1633.severity = none    # no file banners; type header lives in <summary>
  dotnet_diagnostic.SA1600.severity = error   # documentation (csharp-xml-documentation)
  dotnet_diagnostic.CS1591.severity = error
  indent_style = tab                          # Pivot indents with tabs
  ```
- 🟡 **R5.** When the organization publishes an analyzer meta-package again, replace the explicit list with it in one PR.

## 2. Build configuration

- 🔴 **R6.** `TreatWarningsAsErrors` = `true`.
- 🔴 **R7.** `Nullable` = `enable`.
- 🔴 **R8.** `EnforceCodeStyleInBuild` = `true`.
- 🔴 **R9.** CI runs `dotnet format --verify-no-changes`.
- 🔴 **R10.** Generated code excluded by path or `<auto-generated>`, never by disabling rules globally (Pivot's Sonar config already excludes `**/Migrations/**`, `**/*.Designer.cs`, `**/*AssemblyReference*`).
- 🟡 **R11.** Analyzers also run on test projects, with a narrower test `.editorconfig`. `CS1591 = none` for tests does **not** exempt them from documentation (SA1600 stays on).

```xml
<!-- Directory.Build.props -->
<Project>
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <LangVersion>latest</LangVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
    <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
    <AnalysisLevel>latest-recommended</AnalysisLevel>
    <GenerateDocumentationFile>true</GenerateDocumentationFile>
    <ContinuousIntegrationBuild Condition="'$(CI)' == 'true' Or '$(TF_BUILD)' == 'true'">true</ContinuousIntegrationBuild>
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="SonarAnalyzer.CSharp" PrivateAssets="all" />
    <PackageReference Include="StyleCop.Analyzers" PrivateAssets="all" />
    <PackageReference Include="Meziantou.Analyzer" PrivateAssets="all" />
    <AdditionalFiles Include="$(MSBuildThisFileDirectory)stylecop.json" Link="stylecop.json" />
  </ItemGroup>
</Project>
```
```xml
<!-- Directory.Packages.props (excerpt) -->
<Project>
  <PropertyGroup>
    <ManagePackageVersionsCentrally>true</ManagePackageVersionsCentrally>
  </PropertyGroup>
  <ItemGroup>
    <PackageVersion Include="SonarAnalyzer.CSharp" Version="<pinned>" />
    <PackageVersion Include="StyleCop.Analyzers" Version="<pinned>" />
    <PackageVersion Include="Meziantou.Analyzer" Version="<pinned>" />
    <PackageVersion Include="Pivot.Framework.Domain" Version="<pinned Pivot version>" />
    <!-- all Pivot.Framework.* packages share one version: pin them together -->
  </ItemGroup>
</Project>
```

**Pivot.Framework repository status (gap to close, do not copy):** its `Directory.Build.props` currently sets only
TFM/Nullable/ImplicitUsings/LangVersion and package metadata; package versions are inline in each `.csproj` (no CPM),
no analyzers, no `TreatWarningsAsErrors`, no `GenerateDocumentationFile`. Adopt the above in the framework per §6
(legacy adoption), not in one big-bang PR. Note the publish workflow rewrites `<Version>` in every csproj — keep that
element when introducing CPM.

## 3. SonarCloud project

- 🔴 **R12.** Every repository producing a deployable artifact or package has a SonarCloud project (Pivot.Framework: key `AnnabiGihed_Pivot.Framework`, org `annabigihed`, `.github/workflows/sonarqube.yml`).
- 🔴 **R13.** The binding matches where PRs are reviewed (GitHub for Pivot; Azure DevOps or GitHub Enterprise for services). Verify on a real decorated PR — a missing status fails silently.
- 🔴 **R14.** New Code definition: "previous version" for released packages (Pivot's `vX.Y.Z` tags), "number of days" for continuously deployed services; never a fixed date.
- 🔴 **R15.** Analysis runs on pull requests and publishes a PR status.
- 🟡 **R16.** Analysis consumes the coverage report of the same run (OpenCover format).

```yaml
# GitHub Actions (as Pivot's sonarqube.yml) — essentials
- run: dotnet tool update dotnet-sonarscanner --tool-path ${{ runner.temp }}/scanner
- run: >
    ${{ runner.temp }}/scanner/dotnet-sonarscanner begin /k:"<org>_<repo>" /o:"<org>"
    /d:sonar.token="${{ secrets.SONAR_TOKEN }}" /d:sonar.host.url="https://sonarcloud.io"
    /d:sonar.cs.opencover.reportsPaths="TestResults/*/coverage.opencover.xml"
    /d:sonar.exclusions="**/Migrations/**,**/*.Designer.cs,**/*AssemblyReference*"
- run: dotnet format --verify-no-changes
- run: dotnet build -c Release
- run: dotnet test -c Release --no-build --collect:"XPlat Code Coverage;Format=opencover" --results-directory TestResults
- run: ${{ runner.temp }}/scanner/dotnet-sonarscanner end /d:sonar.token="${{ secrets.SONAR_TOKEN }}"
```
Azure Pipelines equivalent: `SonarCloudPrepare@2` (scannerMode MSBuild, same exclusions and coverage path) → format → build → test with coverage → `SonarCloudAnalyze@2` → `SonarCloudPublish@2`.

Coverage exclusions (`sonar.coverage.exclusions`) are allowed only for code that genuinely cannot be unit-tested
(platform code such as MAUI/Blazor auth flows) and must be listed in `README.md` under Tooling deviations. Pivot
currently excludes several packages because they have no test project — track each as debt, don't add more.

## 4. Quality gate
- 🔴 **R17.** Gate on new code only (Clean as You Code).
- 🔴 **R18.** Conditions defined once in the shared gate: no new issues above the agreed severity, hotspots reviewed, new-code coverage and duplication at the organizational thresholds.
- 🔴 **R19.** The gate is a **required** status check on the protected branch (Pivot: `master`). A gate that doesn't block is a dashboard.
- 🔴 **R20.** No project-specific gates.
- 🟡 **R21.** Fix a failing gate; mark a genuine false positive individually in SonarCloud with a justification referencing the PR.

## 5. Suppressions
- 🔴 **R22.** Every suppression carries the rule ID, justification and author at the point of use. *Analyzer:* S1309.
- 🔴 **R23.** `// NOSONAR` only as last resort; prefer a `#pragma` naming one rule.
- 🔴 **R24.** "Won't fix"/"False positive" in SonarCloud need the same justification; never bulk-resolve to turn a gate green.
- 🔴 **R25.** Project-wide suppression requires a waiver ADR with an expiry date; an expired waiver blocks the next release.
- 🟡 **R26.** Suppression counts reported quarterly.

```csharp
#pragma warning disable CA1031 // Background loop must survive any failure; logged and retried next cycle. @gihed 2026-09-29, PIVOT-17
catch (Exception ex) when (ex is not OperationCanceledException)
#pragma warning restore CA1031
```
Existing Pivot pattern: `#pragma warning disable CS0618 // Intentional call to obsolete forwarder` in `BaseDomainErrors` — add author/date when you touch it.
Never suppress complexity, parameter-count or nesting rules; decompose (`clean-code-functions`).

## 6. Legacy repositories (including Pivot.Framework itself)
- 🔴 **R27.** Adopt by enabling the analyzer set and the new-code gate first; never a repository-wide clean-up PR.
- 🟡 **R28.** If `TreatWarningsAsErrors` produces too many failures, escalate rule by rule each sprint under a waiver ADR with a dated plan.
- 🟡 **R29.** Attack debt at SonarCloud hotspots with dedicated tickets and tests.

## 7. IDE parity
- 🟡 **R30.** Same findings locally: shared `.editorconfig`, analyzers, SonarQube IDE extension in connected mode.
- 🟡 **R31.** A pre-commit/pre-push hook runs `dotnet format --verify-no-changes`.
- 🟢 **R32.** Repository-specific analyzers on top of the shared set, documented in `README.md`.

## 8. Checklist
- [ ] The shared analyzer set referenced once in `Directory.Build.props`, versions pinned in `Directory.Packages.props` (Pivot packages pinned together).
- [ ] `TreatWarningsAsErrors`, `Nullable`, `EnforceCodeStyleInBuild`, `GenerateDocumentationFile` set.
- [ ] No local thresholds; no relaxed 🔴 rules without a waiver ADR; SA1124 off, SA1123/SA1600/CS1591 on.
- [ ] CI runs format check, build, tests with coverage and SonarCloud on PRs; gate is a required check.
- [ ] Every suppression is targeted with rule ID, justification, author, date/ticket.
