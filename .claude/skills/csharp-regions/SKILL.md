# C# `#region` layout (Pivot.Framework style)

Every member of every C# type sits inside a named `#region`. This is the convention Pivot.Framework already follows
(≈320 source files); apply it to all code you write — in the framework and in services built on it — and to every type
you touch. Regions are **not** a smell here and are not "section dividers" (see `clean-code-comments`).

## Core rules

1. **Every member is in exactly one region.** No field, constructor, property, method, event, operator or nested type outside a region.
2. **One region per member category**, using the names below. A category with a single member still gets its region.
3. **Omit empty regions.**
4. **Close with a bare `#endregion`.** Do not repeat the name (Pivot: 507 bare vs 4 named). The only exception is a sub-region inside a large region (see *Nesting*), which may repeat its name for readability, as `BaseDomainErrors` does (`#endregion NotFound`).
5. **Type level only.** Never inside a method body, accessor, lambda or statement block; never around `using` directives, the namespace, type attributes or several types.
6. **Title Case, plain names.** No decorations, numbering, emojis or punctuation. Singular/plural as listed (always `Constructors`, never `Constructor`).
7. **Touching a type means regioning the whole type** in the same change. Move members, never rewrite them.
8. **Never add regions to generated code** (`*.g.cs`, `*.Designer.cs`, `*.feature.cs`, `<auto-generated>`, EF migrations).

## Canonical names and order

Skip categories the type does not have.

| Order | Region | Contains |
|---|---|---|
| 1 | `Constants` | `const` fields |
| 2 | `Static Instances` | `static readonly` well-known instances (`Error.None`, cached settings) |
| 3 | `Fields` | instance fields, incl. injected dependencies (`_logger`, `_dbContext`) and backing collections (`_domainEvents`) |
| 4 | `Properties` | properties and indexers (split into `Public Properties` / `Non-Public Properties` only when both are substantial) |
| 5 | `Constructors` | static ctor, instance ctors (incl. the parameterless EF Core ctor), finalizer |
| 6 | `Factory Methods` | static `Create`/`TryCreate`/`Rehydrate` |
| 7 | *Topical regions* | cohesive groups named after their concern, e.g. `Domain Behaviours`, `Domain Events`, `Versioning`, `Soft Delete`, `Serialisation`, `Audit` |
| 8 | `Public Methods` | public methods not covered by a topical region |
| 9 | `<Interface> Implementation` | members implementing an interface, e.g. `IInboxService Implementation`, `IDisposable Implementation`, `IAsyncDisposable Implementation` |
| 10 | `Protected Methods` | protected / protected internal methods (incl. `virtual` extension points) |
| 11 | `Internal Methods` | internal methods |
| 12 | `Operators` | operator overloads and conversions |
| 13 | `Equality` | `Equals`, `GetHashCode`, `EqualsCore`, `GetHashCodeCore`, `CompareTo` |
| 14 | `Overrides` | other overrides (`ToString`) |
| 15 | `Private Helpers` | private methods and static helpers |
| 16 | `Nested Types` | nested classes, records, enums, delegates |

`Private Helpers` is the Pivot name for private methods — do not introduce `Private Methods` in new code.

## Specialized layouts

- **Interfaces:** `Properties` → `Methods` → `Events`.
- **Aggregates / entities** (`AggregateRoot<TId>` etc.): `Fields` → `Properties` → `Constructors` (private EF ctor + private full ctor) → `Factory Methods` → `Domain Behaviours` → `Private Helpers` (invariant guards).
- **Value objects** (`ValueObject<T>` / `StronglyTypedGuidId<T>`): `Constants` → `Properties` → `Constructors` → `Factory Methods` → `Domain Behaviours` → `Equality` → `Overrides` → `Private Helpers`.
- **Command / query / event handlers:** `Fields` → `Constructors` → `Public Methods` (the single `Handle`/`HandleWithResultAsync`) → `Private Helpers`. Primary-constructor handlers with only `Handle` still wrap it in `Public Methods`.
- **Middleware / interceptors:** `Fields` → `Constructors` → `Public Methods` (`InvokeAsync` / overrides) → `Private Helpers`.
- **DI extension classes and EF `IEntityTypeConfiguration<T>`:** `Public Methods` (or `Configuration` for `Configure`) → `Private Helpers`.
- **Blazor code-behind (`.razor.cs`):** `Injected Services` → `Parameters` → `Fields` → `Properties` → `Lifecycle Methods` → `Event Handlers` → `Private Helpers` → `IDisposable Implementation`.
- **Controllers / endpoint classes:** `Fields` → `Constructors` → `Endpoints` → `Private Helpers`.
- **xUnit test classes (framework repo):** `Test Infrastructure` (fixtures, factories, doubles) → one region per behaviour group (`Happy Path Tests`, `Commit Tests`, `Bypass Tests`, …) — as in `Tests/*`.
- **Reqnroll step definitions:** `Fields` (scenario state; sub-regions per concern allowed) → `Constructors` → `Given Steps` → `When Steps` → `Then Steps` → `Step Argument Transformations` → `Private Helpers`.
- **Records with a primary constructor and no body** and **enums** need no regions.

## Nesting
At most one level, only inside a region holding more than five members with distinct concerns
(e.g. `BaseDomainErrors.General` groups each error factory pair in `#region ValueIsRequired` … `#endregion ValueIsRequired`).

## Formatting
- `#region` indented like the members it contains (tabs — the repo indents with tabs).
- **No blank line directly after `#region` or directly before `#endregion`** (dominant Pivot style; some older files have blank lines — normalise when you touch them).
- One blank line between `#endregion` and the next `#region`.
- XML docs and attributes stay attached to their member, inside the region.

## Example (Pivot style)

```csharp
namespace Orders.Application.Features.Orders.Commands.ShipOrder;

/// <summary>
/// Author      : Gihed Annabi
/// Date        : 09-2026
/// Purpose     : Handles <see cref="ShipOrderCommand"/> by loading the order aggregate, applying the
///              ship behaviour and committing through the unit of work (audit + outbox in one transaction).
/// </summary>
internal sealed class ShipOrderCommandHandler : ICommandHandler<ShipOrderCommand>
{
	#region Fields
	private readonly IOrderRepository _orders;
	private readonly IUnitOfWork<OrdersDbContext> _unitOfWork;
	#endregion

	#region Constructors
	/// <summary>
	/// Initialises a new <see cref="ShipOrderCommandHandler"/>.
	/// </summary>
	/// <param name="orders">Repository of the order aggregate.</param>
	/// <param name="unitOfWork">Unit of work committing the aggregate and its outbox messages.</param>
	public ShipOrderCommandHandler(IOrderRepository orders, IUnitOfWork<OrdersDbContext> unitOfWork)
	{
		_orders = orders ?? throw new ArgumentNullException(nameof(orders));
		_unitOfWork = unitOfWork ?? throw new ArgumentNullException(nameof(unitOfWork));
	}
	#endregion

	#region Public Methods
	/// <inheritdoc />
	public async Task<Result> Handle(ShipOrderCommand command, CancellationToken cancellationToken)
	{
		var order = await _orders.FindByIdAsync(new OrderId(command.OrderId), cancellationToken);
		if (order is null)
			return Result.Failure(OrderErrors.NotFound, ResultExceptionType.NotFound);

		var shipped = order.Ship();
		return shipped.IsFailure ? shipped : await _unitOfWork.SaveChangesAsync(cancellationToken);
	}
	#endregion
}
```

## Analyzer settings
StyleCop SA1124 forbids regions; disable it. SA1123 (regions inside elements) stays an error:
```ini
[*.cs]
dotnet_diagnostic.SA1124.severity = none
dotnet_diagnostic.SA1123.severity = error
```

## Review checklist
- [ ] No member of a touched type sits outside a region; names and order match the tables above.
- [ ] Bare `#endregion`; no empty regions; no regions inside member bodies or generated files.
- [ ] `Constructors` (plural), `Private Helpers` for private methods, `Methods` only in interfaces.
- [ ] No blank line right after `#region` / before `#endregion`; tabs for indentation.
