# Pivot.Framework.Authentication.API

Location: `Src/Containers/Authentication/Pivot.Framework.Authentication.API`. References Authentication core only
(uses `System.IdentityModel.Tokens.Jwt` transitively). Implementations of the services come from
`AddKeycloakIdentityProviderServices` in the **AspNetCore** package.

## Registration

```csharp
builder.Services.AddAuthenticationApi();                                   // just AddEndpointsApiExplorer()
builder.Services.AddKeycloakIdentityProviderServices(builder.Configuration); // Pivot.Framework.Authentication.AspNetCore
builder.Services.AddInMemoryAuthSessions();                                 // optional IAuthSessionStore (dev only)

var app = builder.Build();
app.MapAuthenticationApi("/auth");         // returns the RouteGroupBuilder (tag "Authentication")
```
Customize the group (rate limiting, CORS, auth) via the returned builder:
```csharp
app.MapAuthenticationApi("/auth").RequireRateLimiting("auth").RequireCors("spa");
```

## Endpoints (`AuthenticationApiHandlers`, all public static — reusable in your own routes)

| Route | Body → Service | Response |
|---|---|---|
| `POST /auth/login` | `AuthAuthorizationRequest { RedirectUri*, Scope?, State?, CodeChallenge?, CodeChallengeMethod = "S256", LoginHint?, Prompt? }` → `BuildAuthorizationUrlAsync` | `200 { authorizationUrl }` |
| `POST /auth/callback` | `AuthCodeExchangeRequest { Code*, RedirectUri*, CodeVerifier?, SessionId? }` → `ExchangeAuthorizationCodeAsync` | `200 AuthTokenResponse` (+ session saved if `SessionId` and a store exist) |
| `POST /auth/refresh` | `AuthRefreshTokenRequest { RefreshToken*, SessionId? }` → `RefreshTokenAsync` | `200 AuthTokenResponse` (+ session updated) |
| `POST /auth/logout` | `AuthLogoutRequest { RefreshToken?, IdTokenHint?, SessionId? }` → `LogoutAsync` | `200` (+ session removed) |
| `GET /auth/profile` | `Authorization: Bearer …` → `GetUserProfileAsync` (userinfo) | `200 IdentityProviderUser` or `401` |
| `POST /auth/introspect` | `IntrospectTokenRequest { Token }` → `IntrospectTokenAsync` | `200 TokenIntrospectionResult` |
(`*` = required; missing → `ArgumentException` → 500 unless you add exception handling.)

Session persistence (`PersistSessionAsync`): when `SessionId` is provided and an `IAuthSessionStore` is registered, stores
`AuthSession { SessionId, SubjectId (sub/nameid), Username (preferred_username), AccessToken, RefreshToken, ExpiresAt }`,
parsing the access token **without validation** (it just came from the IdP over TLS).

## Security considerations (read before exposing)
- No endpoint calls `RequireAuthorization()` — `/introspect` in particular lets any caller probe tokens using your admin client credentials. Protect it (`app.MapAuthenticationApi().RequireAuthorization("Admins")` or map handlers individually).
- `/callback` and `/refresh` return raw tokens (including refresh tokens) in the JSON body. For browser clients prefer a BFF that keeps tokens server-side and issues an HttpOnly cookie (store tokens in `IAuthSessionStore` and return only the `SessionId`), or use `pivot-auth-blazor`.
- The PKCE `code_verifier` is generated by the client and must be sent to `/callback`; `state` validation is the client's responsibility (the API does not store state).
- IdP errors surface as `HttpRequestException` → 500 via `ExceptionHandlerMiddleware` (detail hidden in Production). Wrap handlers if clients need 400/401 semantics for `invalid_grant`.
- `InMemoryAuthSessionStore` is per-process: use a distributed implementation when running multiple replicas.

## Typical SPA flow through this API
1. Client creates `code_verifier`, `code_challenge`, `state`; `POST /auth/login { redirectUri, codeChallenge, state }` → redirect browser to `authorizationUrl`.
2. Keycloak redirects back to the SPA with `code` + `state`; SPA checks `state`, then `POST /auth/callback { code, redirectUri, codeVerifier, sessionId }`.
3. SPA calls APIs with the access token (APIs use `pivot-auth-aspnetcore`), refreshes via `/auth/refresh`, logs out via `/auth/logout` (+ optionally revoke the access token with `pivot-auth-caching`).

## Changing this package
Keep it provider-neutral: handlers depend only on the `I…Service` interfaces and `IAuthSessionStore`. Tests:
`Tests/Pivot.Framework.Authentication.Tests/API/AuthenticationApiTests.cs` — route registration is asserted by building a
`WebApplication` and reading `EndpointDataSource` route patterns; handlers are invoked directly with NSubstitute services.
